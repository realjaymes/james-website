A plan for Zenrows

Zenrows in the Agent Developer's Stack: A Baseline and a First 90 Days

James Praise · Marketing and GTM Operator

Everything here comes from public data I pulled on 14 November 2026: package downloads, GitHub search and the reading lists agent developers use to pick tools. I can't see your signups, your API traffic by source or which integrations people use, so anything that needs your data is marked [proof needed]. An MCP (Model Context Protocol) server is the plug that lets an AI agent such as Claude or Cursor call a tool.

The plan

The baseline

Your job posting says the goal is to make Zenrows "part of every agentic developer's stack" and that success is measured on adoption. So I measured where adoption shows up in public today, for Zenrows and four tools developers compare you with.

What the numbers say

Your product is not the problem. Your posting reports more than 10 billion requests a month, and much of that traffic probably calls your API directly, which no download count sees. The gap sits further up: Firecrawl's Python package is downloaded about 48 times as often as yours, and agent developers meet it first.

The clearest finding is the last column. Your official MCP server, your CLI and your Cursor and Copilot plugins are all live on GitHub. None of them appears in awesome-mcp-servers or awesome-agent-skills, the lists where agent developers go to choose tools. Firecrawl is listed in both, and Browserbase has ten lines in the skills list.

Week one

The first week costs no budget. I would submit the MCP server, the CLI and the agent skills to the main agent tool lists and MCP directories, each with a short working example. Then I would add a "used by agents" check to every tool comparison you already publish, so a developer who finds you through a list lands on a page that answers the same question.

The first 90 days

Days 1 to 30: get listed and get a baseline

I'd finish the listings and set up a monthly footprint report from the script behind this page. Then I'd talk to ten developers who signed up in the last quarter about what they were building and where they found you.

Days 31 to 60: starter kits and demos

I'd build three starter kits around the jobs agent developers ask about most, such as an agent that reads a protected product page and a research agent that cites live pages. Each kit becomes a video, a GitHub repository and a post where people already talk about scraping, starting with r/webscraping.

Days 61 to 90: first hackathon and a creator loop

I'd pick one AI agent hackathon where the projects need live web data, and go in person. I'd also invite the developers who write about Zenrows into your creator program, which already pays a fee on delivery and 35% recurring.

How I'd measure it

I'd judge the work on adoption, as your posting asks. The leading numbers are monthly SDK and CLI downloads, MCP server installs and GitHub repositories that use Zenrows. The number that matters is new paying accounts whose first request came from an SDK, the CLI or the MCP server. The baseline for that one is [proof needed].

Appendix

How I counted

I wrote a small Python script that calls four public sources: the PyPI Stats API for last-month downloads, the npm download counts API, the GitHub repository search API for repositories whose name, description or README mentions each tool, and the README of each agent tool list.

The packages counted are zenrows, firecrawl-py and @mendable/firecrawl-js, scrapingbee, browserbase and @browserbasehq/sdk, and apify-client. The five lists are awesome-mcp-servers, awesome-llm-apps, awesome-agent-skills, awesome-claude-code and awesome-ai-agents. A line counts when it names the tool.

These numbers have limits. Downloads include automated installs from build pipelines. Apify is also a common word in repository text, so its repository count runs high. None of it measures paying customers. I use it as a footprint, a number that moves when developer relations works, and I would rerun the same script each month.

What I need from you

I would need signups and paying accounts by first-request source (API, SDK, CLI or MCP), which integrations drive the most usage, and the questions support hears most often. Those decide which starter kits come first and which hackathons are worth the travel.

What I read

I read your job posting, your About page, your Community page with the creator program offer, and the public repositories in your GitHub organisation, all on 14 November 2026. Your Community page lists GitHub, X, Reddit, the blog and LinkedIn. It does not list a Discord or a forum you run.

My own work behind this approach: I built a prospect data engine in Python, including a GitHub search and Hacker News adapter that pulled 784 repositories for developer-traction targeting. I also publish 34 of my agent skills at github.com/realjaymes/marketingagentskills.
